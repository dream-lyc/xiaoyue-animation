## Context

项目为新建应用，现有资产是 `design/prototype-v1/export.pdf` 和 Pencil 可编辑原型。主要使用者是遥控器操作的儿童，以及用电脑浏览器维护片库的家长。产品范围以 proposal.md 和本 change 的 specs 为准；原型缺少的登录、扫描错误、空状态等必须补齐。

## Goals / Non-Goals

**Goals:**
- 一个 APK 同时承载 TV 播放、本地数据库和桌面管理服务，外部资源源独立存在。
- 自动扫描和辅助匹配减少维护工作；任何识别失败都可手工完成。
- 将资源文件、逻辑剧集、观看事件和展示资料解耦，保持历史与标签稳定。
- TV 与 Web 使用同一领域服务计算额度和统计，行为一致。

**Non-Goals:**
- 不实现网盘聚合引擎、网盘厂商直接接入、字幕下载、服务端转码、手机 Web 适配、云端账号或跨电视同步。
- 第一版按家庭单台电视的一套观看记录和额度设计，不建立多个儿童账号。
- 不承诺任意视频识别成功、任意 Android 盒子解码成功或电视休眠后管理服务永远在线。

## Decisions

### 1. Android 本地优先架构

拟采用 Kotlin、Compose TV、Media3、Room/SQLite；桌面管理采用 TypeScript + React 构建静态资源，随 APK 打包。内嵌 HTTP 服务采用可在 Android 运行的 Kotlin/JVM 服务器实现，具体库与依赖版本在兼容性验证任务中锁定。拟定最低 Android 8/API 26，支持 arm64-v8a 与 armeabi-v7a；target SDK 按发布渠道要求在实施时确认。这是第一版兼容目标，不是已验证的设备承诺。

模块划分：Android TV UI、Web Admin、Domain（片库/额度/统计）、Storage、SourceAdapters、MetadataProviders、EmbeddedServer。TV UI 直接调用 Domain，Web 经 `/api/v1` 调用相同 Domain。只有一个本地数据库写入入口，不通过浏览器保存权威数据。

选择原生 TV 播放而非把整个产品做成 WebView，以便遥控器焦点、播放器和生命周期统一控制。选择内嵌服务而非强制家长部署另一台服务器，符合已确认需求。

### 2. 资源扫描与播放定位

统一 SourceAdapter 接口：testConnection、listDirectories、listFiles、stat、openRange、resolvePlayback。OpenList/AList 使用外部服务接口，NAS 支持 SMB2/3 与 WebDAV。凭据留在电视，浏览器响应不返回原始令牌；短期播放 URL 按需获取，不作为文件身份。

选定目录后创建持久化 ScanJob，分阶段展示发现、匹配、补全和完成数量。扫描支持取消、重试、断点恢复和幂等更新；网络不可用不得当成目录为空。文件删除只标记不可用，不级联删除剧集或历史。

优先使用源端稳定 ID；否则使用 sourceId + 规范化路径定位。文件移动时通过已有标识/指纹辅助匹配，无法证明同一文件时要求人工关联，不能仅凭名称或弱 hash 自动合并。视频播放地址失效时允许重新解析；SMB 使用受认证的随机读取数据源桥接播放器，不启动转码服务。

### 3. 自动资料匹配分层

扫描后自动运行匹配任务，无需用户逐集点击。优先级：人工锁定 > 已确认外部 ID/NFO > 名称、目录、季集编号 > moviehash 辅助证据。每个提供方保留 adapter，便于禁用或替换。

对未确认文件，在具备 OpenSubtitles key、源端支持范围读取时，读取文件头尾各 64 KiB 与文件大小计算 moviehash，只调用搜索接口，不下载字幕。要求匹配响应确为 hash 命中；接口可能回退到名称搜索，不能把所有返回项都标为指纹命中。OSHash 不能用于安全去重。数据有冲突或多个候选时进入待确认，无命中时保留未匹配条目。未知文件不因指纹失败而丢弃。

从候选外部 ID 或确认后的动画名称/年份查询 TMDB，取得剧集、季集和图片。只有唯一且证据一致的候选自动确认；仅名称模糊相似不能自动发布为已识别。多集文件、拆分视频和不同播出排序需人工映射；EpisodeAsset 支持时间区间，便于单文件多集的播放边界和限时策略。

密钥未配置时明确显示“自动资料服务未配置”，继续本地扫描和手动维护。429 遵守 Retry-After，服务错误指数退避，有界重试；匹配结果缓存避免重复请求。海报与单集截图分开存储，缺图顺序为本地图片、在线图片、可解码视频截帧、默认占位。失败重试不覆盖人工编辑字段。

### 4. 核心数据模型

| 实体 | 主要职责 |
|---|---|
| Source、SourceRoot、ScanJob | 凭据引用、选定目录、扫描状态与失败原因 |
| MediaAsset、EpisodeAsset | 源端文件身份、可用性、指纹；映射逻辑剧集及可选起止时间 |
| Library、Series、Season、Episode | 稳定 UUID 的片库与动画层级；第一版每部动画归属一个片库 |
| MetadataMatch、FieldOverride、Artwork | 候选、证据、外部 ID、人工字段锁和封面来源 |
| TagKey、TagValue、EpisodeTag | K/V 字典及剧集多对多关系，联合唯一约束避免重复标签 |
| PlaybackSession、WatchInterval、Progress | 幂等实际播放区间、事件归属、续播位置 |
| DefaultPolicy、DailyPolicy、ParentGrant | 默认额度、按日期覆盖值、首启处理标志、收尾剧集和授权记录 |
| AdminSession、BackupManifest | 管理登录会话、备份版本与完整性信息 |

整季/整部打标操作展开到当前匹配的逻辑剧集，展示数量后事务提交；以后新增剧集不静默继承此前批量操作，家长可重新批量应用。追加、移除指定值、替换该 K 的值集合三种操作明确区分。同 K 多选 OR、不同 K AND。

数据库保存在应用私有目录，图片单独缓存，敏感凭据由 Android Keystore 保护。备份包含稳定 ID、片库、标签、事件、策略、人工覆盖和封面；不含视频、会话、可复用授权和明文凭据。跨设备恢复后重新输入源凭据。历史关联软删除实体，不因片库整理失联。

### 5. 计时与每日额度状态机

默认以设备时区作为家庭统计时区，首次设置后固定保存（原型为 Asia/Shanghai）。使用单调时钟计算实际播放秒数，墙上时间用于日期归属。暂停、缓冲、停止不计时，拖动进度不产生观看时长；快进播放按实际经过时间计时。每 5 秒及暂停/切集/退出写入检查点，正常退出不丢时长，异常终止最多丢失一个检查点周期。保存事件、日累计和额度状态在同一事务提交，重复检查点不得重复累计。

日期内额度 = 今日覆盖值或默认值；剩余 = max(0, 额度 − 当日实际观看)。首次进入显示默认额度和跳过/家长设置入口。跳过或返回记为当天已处理；当天再进入不重复询问、不覆盖今日额度。取消验证/编辑回到原流程且不改额度。次日覆盖失效，不删除历史。

状态为 available、finishing-current-episode、locked。额度耗尽时原子记录当前 episodeId 与对应播放边界，只允许恢复该集剩余部分，禁止切换列表、切源到其他逻辑集或自动下一集绕过；收尾阶段禁止倒退/重播来无限延长收尾，允许前进。结束后 locked。父母修改今日总额度时不重置累计：若新剩余 > 0 则 available；否则正在播放时进入/保留本集收尾，未播放时 locked。

进入家长设置而临时暂停的会话仍视为当前未结束剧集；调低额度时可以为此集保留收尾资格。退出播放器且没有既存收尾许可时，不允许通过打开设置重新获得收尾集。

答题挑战在电视服务端随机生成适合口算的单步题：20以内加减法（结果非负）或1—9个位数乘法，由服务端校验并限次；失败 3 次等待 30 秒，新挑战替换旧挑战。验证通过发放短时、绑定操作的一次性授权（拟定 2 分钟），不能当作永久家长登录。保存/取消/过期后失效。支持两种独立操作：修改今日总额度；到时后额外允许下一集一次。额外一集明确绑定剧集且消费授权，结束后重新按额度判定，实际时长仍计入统计。

跨午夜把区间切分到两个日期；新日期重新评估默认额度，正在播放时不弹窗打断，下次进入首页处理首启提示。日期回拨不得清除已有日累计或已消费授权；设备时间异常需提示家长，不能把本应用宣称为防系统管理员绕过的家长控制工具。

### 6. 历史与统计口径

WatchInterval 保存稳定 episodeId、观看时的 libraryId、起止 UTC、统计时区/日、有效秒数及 normal/grace/parent-extra 分类；策略状态转换时拆分区间，以便后来修改额度仍能准确解释当时的收尾与额外授权时间。片库历史按观看时归属，不因后来移动片库转移历史。标签统计则实时关联当前 EpisodeTag，按用户确认追溯全部历史。删除/补加标签后重算缓存。

总时长按事件去重；每个 K/V 单独汇总，重叠标签可以分别包含同一事件。选中多个值后的联合总时长按事件并集计算，不能相加标签行。重复观看真实消耗时间应再次累计，去重的是同一事件的重复上报或标签联结，不是把同一剧集只算一次。TV 和 Web 共用按日/片库/动画/标签查询及每日明细。

### 7. 局域网管理和交互

首次由电视启用管理服务并设置独立管理员密码，屏幕展示局域网地址/端口；Web 账号密码与 TV 答题授权是不同机制。初始通过电视授权的配对流程建立管理凭据。Web 使用限时会话、防暴力尝试、CSRF/Origin/Host 检查；不配置公网穿透，不对匿名访问返回片库或令牌。

默认局域网 HTTP 部署仅定位于可信家庭网络，在启用界面说明传输不加密；HTTPS 作为后续可选部署增强。不能把客户端 JS 内置固定第三方 secret 当成保密方案；来源凭据和用户配置 API key 仅由服务端适配器使用。

管理启用时按 Android 生命周期规则运行服务并显示状态；进程被系统终止/电视断电休眠时 Web 可能不可达。重开 App 恢复服务、扫描任务与策略，不能清空数据。按 0.1.5 的交互调整，播放器采用简洁进度、选集、设置三级浮层：中间与左右键直接控制播放，下键依次进入同播放列表的邻集和设置。浮层仅保留倍速与同集换源等相关选项；家长设置从返回首页后的顶部入口或锁定页进入。

## Risks / Trade-offs

- [国产盒子系统与解码差异] → 先进行最低版本与代表设备验证；不支持编码时明确报错并允许同集切源，不承诺转码。
- [弱命名、合辑、配音/重压版识别率低] → 候选确认、整季映射、手工覆盖；先用真实样本测命中率，不承诺准确率。
- [外部接口限流、网络与授权变化] → 独立适配器、限速缓存、密钥配置、离线已有资料可用；发布前复核 API 与图片使用条款。
- [遥控器可答题，不能证明家长身份] → 明确是家庭操作门槛，授权短时且绑定单次动作。
- [系统强杀与断电] → 小间隔检查点、数据库事务、启动恢复；统计允许最多 5 秒未落盘损失。
- [数据库破坏或误恢复] → 备份完整性验证、恢复前快照、事务恢复；不支持降级直接打开新 schema。

## Migration Plan

新项目无旧数据迁移。按基础骨架、源与片库、播放与计时、家长策略、统计与管理的顺序迭代。首次发布创建版本化数据库；升级迁移前备份并执行迁移测试。失败保留原库与诊断，不自动重建空库。回滚 APK 时恢复兼容版本备份，而非直接读较新的数据库。

## Open Questions

- 实际电视型号未知；API 26 与 ABI 范围为当前假设，实施阶段通过真机矩阵校验，不阻塞规格编写。
- 外部源版本、真实动画样本、OpenSubtitles/TMDB API key 尚未提供；用契约测试和固定样本先开发，真实接入及命中率验证列为发布前任务。
- 是否商业发布尚未确定；发布前按用途完成第三方 API 和图片许可核对。
